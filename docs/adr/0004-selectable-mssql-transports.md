# Selectable MSSQL transports

Orbit will preserve the user-installed `sqlcmd` MSSQL transport and add a JDBC transport because jTDS with explicit domain credentials is the only known way to reach the current test environment. A JDBC connection profile selects `transport = "jdbc"` and a specific JDBC driver, initially `driver = "jtds"`; Orbit runs that driver through an Orbit-owned Java helper and structured protocol using a user-installed Java runtime. This accepts helper maintenance in exchange for retained JDBC sessions and structured results, while omitted `transport` continues to select `sqlcmd` for existing profiles.

Orbit ships the helper as Java source and requires users to provide Java 11 or newer and the jTDS JAR, avoiding bundled runtimes, third-party binaries, and silent downloads. JDBC profiles use validated structured fields, explicit password authentication, NTLMv2 for domain credentials, and encrypted TLS with JVM-trusted certificate-chain validation by default; credentials are delivered to the helper only through its framed stdin protocol. jTDS does not document hostname matching, so Orbit does not claim the default is equivalent to a modern hostname-verified TLS client.
